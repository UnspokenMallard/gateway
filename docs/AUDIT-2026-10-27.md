## Findings (ranked)

1. **[medium, confirmed] [improvement] Telemetry keys do not match surface names.** `fafnir.provider_call` rows carry `surface` (8 surfaces seen in 7 days: `hud-whereami` 748 calls, `mind-improve-subject` 160, `mind-improve-judge` 153, `report-narrate` 11, `inbound-message-triage` 9, and three singles). `fafnir.job_call` rows carry a job name (`hud-audit-nightly`, `nightly-reflection`, `proposer`, `memory-capture`, ...), not the surface. Of the 29 configured surfaces, 20 never appear under their own name in either stream (`escalation`, `inbound-task-triage`, `mind-draft-triage`, `mind-memory-capture`, `mind-session-history`, `mind-vault-capture`, `originate`, `promises-extract`, every `job:*`). Some are only rarely called, but you cannot tell a dead surface from a mislabelled one. Fix: write the surface name on every row in both streams, then list surfaces with 0 calls in 30 days.
2. **[retracted 2026-10-27] `promises-extract` calls leave no trace.** Wrong: the calls are logged as `fafnir.job_call` rows under job `promises` (not under the surface name, see finding 1), cost about $0.0001 each, so the summary rounds to `$0.00`. Haiku answered `{"promises": []}`. The job's real problem was batching, fixed in the Jarvis repo.
3. **[low, confirmed] [underperforming] Failure counts by job over the life of the stream.** `job_call` failures: `hud-audit-nightly` 26 (5 weeks), `nightly-reflection` 5, `proposer` 5, `checkups` 3, `remediate` 3, `weekly-activity` 2; `provider_call` failures: `hud-whereami` 4 of 748 in the last 7 days. The audit job is the clear outlier (hits the $1 per-run cap; see Analyst audit). Gateway could return the reason (`error_max_budget_usd`, timeout, tool denial) in the row so the Jarvis alert stops showing `<empty>`.
4. **[low, confirmed] [improvement] `hud-whereami` volume.** 748 calls in 7 days (about 107 a day, 4.1 s average, $0.32 total). Cheap, but it is the top call source and 4 failed. Fine; worth a rate cap if the HUD adds more auto-summaries.
5. **[low, confirmed] [improvement] Server log is silent.** `state/logs/server.log` was last written 2026-10-18 while the server has run 2 days. Either logging is off or requests are not logged. Add one line per failed call.
6. **[low, unverified] [improvement] Callers that spawn `claude` directly.** Files that match `claude -p` or `"claude"`: `~/.jarvis/daemon/{core,brain,main,scope}.py`, `~/.jarvis/scripts/{jobcommon,run-issue-triage,run-checkups,run-usage-digest,checkup-probe}.py`, `~/.mind/mimir/{agentjob.py,jobs/nightly-reflection.py,jobs/memory-capture.py}`. Some are by design (the brain keeps its caps in Jarvis per `config.toml`), others may be paths to the CLI only. I did not trace each. Make an inventory and mark each as routed, intentional bypass, or to migrate.
7. **[low, confirmed] [improvement] Tests do not run under `unittest`.** `tests/test_bifrost.py` and `test_sessions.py`: `unittest discover` reports `NO TESTS RAN` (function style). Run as scripts; add one documented command.
